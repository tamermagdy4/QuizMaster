# فهلوي — دليل تشغيل نظام الباقات (Quiz Packs)

هذا الدليل يشرح بالخطوات: تطبيق مهاجرات Supabase الخاصة بنظام الباقات، ثم التشغيل الفعلي الكامل
(إنشاء باقة ← اختبار مخصص ← أسئلة ← استيراد ← نشر ← لعب) والتحقق من الصلاحيات.

## 4) التشغيل الفعلي — إنشاء → نشر → لعب

> المتطلبات: تسجيل دخول عادي (حساب لعبة) — لا يلزم حساب أدمن لهذه الخطوات.

### 4.1 إنشاء باقة
1. افتح `/packs` ← زر **سجّل الدخول للإنشاء** (أو **＋ إنشاء باقة** بعد الدخول).
2. املأ: اسم الباقة، الوصف، الفئة، الصعوبة، الظهور (عام/خاص)، غلاف اختياري.
3. **حفظ كمسودة** — يمكنك مغادرة الصفحة والعودة لاحقًا من `/packs/:id/edit`.

### 4.2 إضافة اختبارات (طريقتان)
- **إنشاء اختبار جديد**: زر **＋ إنشاء اختبار جديد** ← الاسم/الوصف/الفئة/الصعوبة/الغلاف ← ينتقل تلقائيًا لمحرر الأسئلة.
- **إضافة اختبار موجود**: من قائمة الاختبارات الحالية (فئات فهلوي) — زر **إضافة**.

### 4.3 كتابة الأسئلة يدويًا
في خطوة **الأسئلة**:
1. اختر الاختبار المخصص من الأعلى.
2. **＋ إضافة سؤال** ← السؤال، الإجابة، النقاط (100/200/300/500/1000)، الصعوبة، تلميح، روابط صور.
3. **حفظ السؤال** — يظهر فورًا في القائمة المرقّمة.
4. التعديل/التكرار/الحذف من أيقونات كل صف؛ **إعادة الترتيب بالسحب** (☰).

### 4.4 استيراد أسئلة (بدل/بجانب الكتابة اليدوية)
1. من خطوة الاختبارات: زر **⬆ استيراد أسئلة** (ينشئ اختبارًا ثم يفتح نافذة الاستيراد).
2. الصق نصًا أو ارفع ملف: `.txt`, `.csv`, `.json`, `.xlsx` (تقرأ أول ورقة عمل).
   - الصيغ النصية المدعومة: `Question:/Answer:` أو `سؤال | إجابة` أو سطر-سؤال ثم سطر-إجابة (يُكتشف تلقائيًا).
   - CSV/Excel: عناوين إنجليزية أو عربية (`السؤال/الإجابة/النقاط/الصعوبة/التلميح/صورة`).
   - JSON: بنية فهلوي `{ "questions": [...] }` أو مصفوفة بسيطة.
3. **المعاينة إلزامية قبل الحفظ**: عدد الصفوف + `✓ صالح / ⚠ يحتاج مراجعة`.
4. أصلح الصفوف غير الصالحة مباشرة في المعاينة (تعديل النص/النقاط، أو حذف الصف).
5. **استيراد** — يُحفظ دفعةً واحدة (إدراج مجمّع، يدعم مئات/آلاف الأسئلة).

### 4.5 تصدير الأسئلة
من محرر الأسئلة: أزرار **JSON / CSV / TXT** — تنزّل ملفًا بنسخة نظيفة من أسئلتك.

### 4.6 النشر
1. خطوة **المراجعة والنشر**: اعرض الملخص (العنوان، عدد الاختبارات، عدد الأسئلة، الظهور).
2. إذا كانت هناك مشكلات (اسم فارغ، لا اختبارات، اختبار بلا أسئلة) ستظهر ⚠ ويمنع النشر حتى تُحل.
3. **نشر الباقة** — تنتقل إلى صفحة الباقة العامة.

### 4.7 اللعب
- من صفحة الباقة: **▶ ابدأ الباقة** (كل الاختبارات بالتسلسل مع تتبع التقدم) أو **ابدأ الاختبار** لاختبار واحد.
- عند فتح سؤال: اقرأه ← **كشف الإجابة** ← قيّم نفسك (صحيحة/خاطئة) ← يُحتسب النقاط.
- تقدم الباقة (x/y اختبارات + شريط تقدم) محفوظ محليًا لكل مستخدم.

## 5) التحقق من الصلاحيات (RLS)

### بائع (مالك الباقة)
| العملية | النتيجة |
|---|---|
| إنشاء باقة/اختبار/سؤال | ✓ يعمل |
| تعديل/حذف باقة واختباراتها وأسئلتها | ✓ يعمل |
| رؤية مسودته وخاصته | ✓ يعمل |

### مستخدم آخر (غير المالك)
| العملية | النتيجة |
|---|---|
| رؤية باقة منشورة + لعبها | ✓ يعمل |
| رؤية مسودة/خاصة لشخص آخر | ✗ محجوب (RLS) |
| تعديل/حذف باقة شخص آخر | ✗ محجوب (RLS + RPC `set_pack_quizzes` يرفض) |
| كتابة أسئلة في اختبار شخص آخر | ✗ محجوب (RLS) |

### أدمن
يرى كل شيء (منشور/مسودة/خاص/مخفي) ويمكنه الإخفاء/الحذف/التمييز من `/admin/packs`
(تبويبات: الباقات، الاختبارات المخصصة، أسئلة الباقات).

## 6) استكشاف الأخطاء

| المشكلة | السبب/الحل |
|---|---|
| `relation "public.packs" does not exist` / 404 على REST | المهاجرات لم تُطبّق بعد — اتبع القسم 2 |
| `42702 column reference "pack_id" is ambiguous` من RPC | **سبب جذري معروف**: في PL/pgSQL، إذا كان اسم معامل (مثل `pack_id`) يطابق اسم عمود في نفس الجملة (DELETE/INSERT) يرفض Postgres رغم استخدام `$1`. الحل المعتمد هو نمط الغلاف (مثل 009/010): الدالة العامة تحتفظ بأسماء المعاملات لـ PostgREST، وتفوّض لدالة داخلية بأسماء بلا تعارض (`p_pack_id`) |
| "Only the pack owner may edit its quizzes." عند الحفظ | RPC `set_pack_quizzes` يتحقق من المالك — سجّل الدخول بحساب المالك |
| إنشاء اختبار يعطي "sign in required" | تحتاج حسابًا مسجّلًا (زر تسجيل الدخول) |
| استيراد Excel يفشل | تأكد أن الملف `.xlsx` فعلي (وليس `.xls` قديم) — يُدعم `.xlsx` فقط |
| "0 packs" في صفحة الباقات رغم وجود بيانات | الباقة لم تُنشر بعد (الحالة `published` مطلوبة للظهور العام) |
| صورة الغلاف لا تُرفع | صيغة غير JPG/PNG/WEBP أو حجم > 5MB — أو bucket غير منشأ (تحقق من القسم 2) |
| سؤال "طويل جدًا" | نص السؤال ≤ 2000 حرف والإجابة ≤ 1000 حرف |

## 6.5) اللعب المباشر Live Pack (مهاجرة 015)

نظام ألعاب مباشرة متعددة اللاعبين فوق الباقات (شبيه Sporcle Live):

- **المضيف**: يفتح الباقة → زر **"إنشاء لعبة مباشرة"** → يحصل على كود غرفة (6 أحرف) + رابط دعوة، ويرى اللاعبين لحظيًا، ثم يضغط **بدء اللعبة**.
- **اللاعبون**: يدخلون من رابط الدعوة (`/packs/live/join?code=…`) أو كود في صفحة الباقات، يكتبون اسمهم ويدخلون اللوبي (حد أقصى 10 افتراضيًا).
- **اللعب**: الجميع يرى نفس السؤال في نفس اللحظة؛ اللاعب يكتب إجابته ويرى "تم الإرسال — بانتظار اعتماد المضيف". **لا تُصحَّح الإجابات تلقائيًا أبدًا** — المضيف وحده يضغط صح/خطأ لكل لاعب، ويمكنه تغيير الحكم (تتحدث النقاط تلقائيًا).
- **التقدم**: زر "السؤال التالي" ينقل الجميع معًا؛ "إنهاء اللعبة" يعرض الترتيب النهائي للجميع.
- **الاتصال**: نبض قلب كل 8 ثوانٍ (قلب/متصل)، والمضيف يمسح المتصلين المنقطعين (30 ثانية). إعادة الدخول بكود الغرفة تعيد الاتصال وتحافظ على النقاط والإجابات. إذا انقطع المضيف يمكن لأي لاعب تولّي المضيف.
- **البيانات**: جداول `live_pack_rooms` / `live_pack_players` / `live_pack_questions` / `live_pack_answers` + Realtime (`postgres_changes`). كل الكتابة عبر دوال أمنية (`live_create_room`, `live_join_room`, `live_start_game`, `live_submit_answer`, `live_review_answer`, `live_next_question`, `live_finish_game`, `live_transfer_host`, …). قاعدة البيانات هي مصدر الحقيقة.
- **سجل الجولات (مهاجرة 029)**: عند إنهاء المضيف للعبة، `live_finish_game` يحفظ لقطة نهائية للترتيب (الفائز + النقاط + إحصاءات كل لاعب) في جدول `live_round_history` في نفس المعاملة — يستطيع المضيف واللاعبون فتح نتائج جولات سابقة من زر **📜 سجل الجولات** في شاشة النهاية. القراءة عبر `live_get_round_history(p_pack_id)` و`live_get_round_history_by_room(p_room_id)` (RLS: قراءة للمصادقين فقط، الكتابة حصرًا عبر الدالة الأمنية).
- **ملخص الجولة السابقة في اللوبي (مهاجرة 030)**: عند "العب مرة أخرى" يمرّر المضيف معرف الغرفة المنتهية (`p_previous_room_id`) فيُحفظ في `live_pack_rooms.previous_room_id` — فيعرض اللوبي الجديد (للمضيف واللاعبين) الترتيب النهائي والفائز من `live_round_history` عبر `live_get_round_history_by_room` قبل بدء الجولة القادمة.
- **العودة الجماعية للاعبين (مهاجرة 031)**: رابط الدعوة للجولة الجديدة يحمل `?code=NEW&prev=OLD` — وعند فتحه ينضم اللاعب إلى اللوبي الجديد **بنقرة واحدة** بنفس اسمه/صورته من الجولة السابقة عبر RPC `live_rejoin_room` (بدل كتابة الاسم يدويًا). زر "العب مرة أخرى" ينسخ الرابط تلقائيًا، وزر "نسخ رابط الدعوة" في اللوبي يتضمنه أيضًا، مع شارة 🔁 "جولة متابعة".
- **اختبار تلقائي**: `node scripts/e2e-live.mjs` (ينشئ حسابين/ثلاثة مؤقتة وينظّف نفسه).
